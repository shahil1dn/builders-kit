# spec

Skip this for tiny changes (a typo, a colour, one small tweak) — just do them.

## Before writing

If the goal is fuzzy, use `/interview-me` first. If `SPEC.md` already exists, read it and update
it instead of starting over.

## Write SPEC.md

Short, plain English, five parts:

1. **What it is** — one paragraph. What will someone be able to do when it's finished?
2. **What's in** — the specific things it will do, as a short list.
3. **What's out** — the things it will deliberately *not* do (yet). This is the most important
   part: it stops the project growing until it never finishes.
4. **How we'll know it works** — for each thing in the list, what they will be able to try and
   see. "I type my name and the page says hello" — not "it works".
5. **Open questions** — anything you still need them to decide. Empty is fine.

## Then

Show them the spec, ask if anything is wrong or missing, and once they're happy suggest `/plan`.
